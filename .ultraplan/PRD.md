## What We're Building
We are building a highly reusable, fast e-commerce template called Ecom OS. It is designed to let the EPIOSO agency launch new online stores for clients in just two weeks instead of months. It features a universal storefront that can connect to different backends (like WooCommerce) and has a built-in system to easily toggle features like languages and payment methods on or off for each client.

## The Problem
Currently, building a custom e-commerce site takes 8 to 12 weeks, which is too slow and expensive for smaller merchants. Existing solutions either lock you into a rigid platform or require building from scratch every time. Ecom OS solves this by providing a premium, fully-featured starting point that is flexible enough to adapt to different clients' needs instantly, while maintaining top-tier speed and design.

## Who It's For
**Small Merchants (Yasmine)**: People running boutique stores (like clothing or cosmetics) who need a beautiful, fast, and mobile-friendly shop to sell to local customers without dealing with technical headaches.
**European Agencies (Marc)**: Partners who need a reliable, fast template to deploy multiple stores for their own clients.
**Mid-Market CTOs (Karim)**: Technical leaders who want a solid foundation to build upon and customize via APIs.

## What It Does
### Must Have (Launch Day)
- Home page with a welcoming hero section and featured products
- Catalog page to browse all products with filtering options
- Product details page showing images, sizes/colors, and an add-to-cart button
- Shopping cart that remembers what you added even if you leave
- Guest checkout flow (address, shipping, payment)
- Customer account pages (login, register, profile, and order history)

### Should Have (Core v1 — restored per pre-dev PRD F-10..16)

- Multi-language support (English, French, Arabic) with full RTL for Arabic (FR-060..065)
- Multiple payment gateways working together (Stripe, CMI, Cash on Delivery) via the multi-payment addon (FR-070..076)
- WhatsApp notifications for new orders (COD provider, FR-076)

### Nice to Have (Future)
- Centralized admin portal for EPIOSO to manage all client deployments

## How It Should Feel
The storefront must feel premium, modern, and minimal. It should use clean typography, plenty of whitespace, and smooth, subtle animations (like items fading in as you scroll). It needs to feel like a high-end native app on a smartphone, complete with a bottom navigation bar and instant loading speeds. It will also support dark mode out of the box.

## What It Connects To
The storefront connects to a WooCommerce backend to get product information and save orders — **through a single typed `EcomEngine` interface (ADR-004)** so the UI never knows which engine is behind it. A second Vendure backend is supported by swapping one env var (`ECOM_ENGINE`), shipping in Sprint D. Payments connect to Stripe and CMI through the multi-payment addon's `PaymentGateway` interface (each provider verifies its own webhook signature before any order state change). COD orders are local; a messaging webhook sends WhatsApp notifications to merchants when a new COD order arrives. i18n translations are edited by merchants in the WordPress admin without a redeploy (companion WP plugin).

## What It Does NOT Do
- It does NOT support multi-vendor marketplaces (like Amazon or Etsy); it is for single-brand stores only.
- It does NOT deduct automatic platform fees from merchant sales.
- It does NOT have a custom master admin dashboard in version 1; deployments are managed via standard hosting tools.

## How We'll Know It Works
- The website loads extremely fast on mobile phones (scoring 90 or higher on Google's Lighthouse test) — **enforced as a CI gate** (NFR-001..004).
- A shopper can browse, add to cart, and checkout seamlessly without errors.
- The shopping cart stays saved if the user closes their browser and comes back within 30 days (SR-SESS-002).
- Every payment webhook is signature-verified before any order state change (NFR-033, FR-074/075) — tested with tampered-signature cases.
- Swapping the backend engine (`ECOM_ENGINE`) needs no UI code changes (FR-014).

## Business Model
EPIOSO will monetize Ecom OS by charging clients a one-time setup fee per project, plus an optional monthly retainer for ongoing maintenance and support. The merchants themselves keep 100% of their sales revenue.

## Risks & Concerns
1. **Performance vs Animation:** GSAP animations vs Lighthouse ≥ 90 (NFR-003: hydrated JS ≤ 180KB gzip). Mitigation: animations isolated in client islands, `useGSAP` cleanup, no layout-thrashing. (Section 05.)
2. **Cart sync without bundle bloat:** Zustand store mirrors server state; server is source of truth. (Section 06.)
3. **Webhook synchronization:** WC product changes → storefront within 60s via webhook-driven ISR (`revalidatePath` + `REVALIDATE_SECRET`). (Section 10, FR-024.)
4. **CMI integration (added):** highest-risk component — HMAC signature verification, replay protection, 3DS redirect; poorly documented, needs real merchant creds. Start outreach now (charter R-03). (Section 09.)
