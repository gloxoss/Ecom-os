## Regression design

Write meaningful failing boundary tests before repair where possible. Do not write tests that only assert a value supplied by their own literal fixture. Unit/mock proof, backend transactions, browser execution and operational restore are separate evidence classes. Never count a draft order ID, build success or screenshot as full purchase proof.

## Evidence and rollback

Record tested checkout SHA/path, tool versions, exact command results, fixture IDs and what was not run. Verifier must independently check the submitted SHA in a clean/detached inspection checkout. Revert only the owned slice; staging fixtures/migrations require their documented namespace backup/restore. Preserve other agents' changes and protected submodule. Final checkpoint is not automatically passed because its parent task was historically accepted.

Hard section dependencies: none. Runtime hub phase prerequisites remain []. No new owner decision is required for authorized local work in this scope.

## Reconciliation is not runtime certification

Each audit checkpoint resolves when the evidence has been independently classified, including an honest tool/environment BLOCKED result. Missing browser capability can permit contained catalog development while runtime and release certification stay withheld; an exposed P0 forbids activation until repair. Phase-1 dependency on this section is the recorded containment/reconciliation decision, not an invented browser PASS. ECO-901 retains the hard actual production-browser release proof.

## Test design checkpoint

This section reproduces existing decisive checks and actual server/browser behavior. It creates no application test placeholder and never treats an unexecuted test as proof.
