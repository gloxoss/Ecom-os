## Findings and repair acceptance

### A-01, high: production runtime evidence is mislabeled

`docs/ecomos/PHASE_0_REPORT.md:52` retains a blocked browser check while line 74 describes a verified runtime check. `scripts/verify-production-runtime.mjs:20` imports and invokes source functions directly. Lines 71–78 tolerate missing Next server-context errors. Setting production environment variables does not start a production server.

Retain this script as unit/contract evidence. Separately run a built Next server and HTTP/browser smoke with actual rendered nonce/CSP, hydration, catalog/PDP/assets, dotted account paths, disabled API boundaries, private headers and revalidation rejection/success. Capture server command, checked-out SHA, redacted network/browser output and exit result. Never convert a tool blocker into a pass.

### A-02, high: verification execution provenance is insufficient

`.agent-hub/PROTOCOL.md:25` requires a clean/detached exact-SHA verification checkout. `.agent-hub/hub.mjs:187` compares the supplied SHA and distinct actor ID, then records supplied text; it does not execute checks or verify the verifier's checked-out HEAD. Registrations point at the shared repository. Full install/verify/build verdicts follow some submissions within approximately 15–26 seconds, without retained independent command logs or corresponding install/build claims. This is a reason to reproduce, not proof of fabricated results.

For the next checkpoint record real checkout path/HEAD, initial dirtiness, tool versions, command output, fixture origin and verifier identity. Use an isolated inspection checkout and coordinate shared resources. Acceptance is scoped to what ran. Reopen a task if reproduced behavior violates its acceptance; do not edit journal flags manually.

### A-03, medium: historical backend smoke is treated as fresh verification

`docs/ecomos/verification/ECO-008/verification.md:20` reviews JSON artifacts. Their last change predates the ECO-008 documentation submission, at commit `148e913`. Preserve order #15 as historical synthetic backend proof. It does not establish a new independently executed staging smoke, concurrency safety, frontend sessions, merchant shipping/tax policy or browser order confirmation.

Reproduce a controlled isolated backend smoke when the staging resource is available, then require the full Phase 2 browser purchase gate separately. Sequential rejection of a retry does not prove concurrent duplicate protection.

### A-04, medium: ECO-101 tests prove less than the summary implies

`packages/ecom-engine/src/__tests__/contracts.test.ts:25` claims export coverage but asserts that `FakeEngine` exists. Lines 291–296 inspect keys of a local literal, not the package source. Many tests assert values the fixture itself supplied. Canonical money parsing does have meaningful negative tests, but that is not runtime validation of all ten domain types.

Keep ECO-101 acceptance scoped to typed specification and compatibility. Before dependent mapping acceptance, specify canonical aliases (`variations` versus `variants`, inventory versus legacy stock quantity), category identity, unknown inventory, variable-price/range semantics and brand cardinality. Add negative boundary/projection tests where data crosses the adapter; no need to manufacture a universal runtime schema library.

### A-05, low: neutrality assertion needs narrowing

The field surface in `types.ts` is generic. `contracts.test.ts:167`, `:173`, `:245` includes blood-pressure, Tensiomètres and Diagnostic fixtures. State “generic domain surface without ParaLoca business fields,” or neutralize the fixtures. This vocabulary alone is not proof that the commerce architecture is client-specific.

### A-06, high before Phase 1 acceptance: committed catalog implementation is incomplete

At the audited commit, `products.ts:39`, `:60`, `:113` convert upstream errors into absent data; category handling, pagination beyond 20 and query metadata are incomplete. `mappers.ts:5` retains only a featured image and basic money while omitting the required rich catalog projection. These are planned ECO-102/103 work, not a new regression.

Current uncommitted ECO-102 edits already add portions of errors, mapping and top-level pagination. They are not audited/accepted by this report. Check completeness of nested connections independently: bounded `variations(first:50)` or categories `first:100` cannot prove a complete catalog. Related items and slugs belong to ECO-102 too, although the pasted next-task list omitted them.

### A-07, Phase 2 blocker: exact variation does not yet survive shopper intent

At the baseline, cart-store merges by parent product ID; add-to-cart selects the parent; checkout serialization lacks exact variation identity. Checkout remains contained/disabled, so no incorrect live order is demonstrated. Preserve product ID, variation ID, selected attributes, SKU, quantity and Woo line key through cart operations. Browser price is never order authority.
